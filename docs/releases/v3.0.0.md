# ADK UI v3.0.0

ADK UI 3 adds to ADK-Rust 3's agent-drawn UI instead of competing with it. `adk-surface`'s
`genui` feature does the drawing:
- it draws, versions and records every drawing;
- it keeps approval controls, secrets and links out of drawings (spec 3.3 §7.4 rule 5);
- it turns a form's **Send** into a call the person decides.

adk-ui 3 adds what `genui`'s `forms` catalog leaves out (charts, metrics, pages and 3D) as
**extension catalogs**, which `genui` checks and draws. adk-ui has no render tool, protocol,
provenance record or approval path of its own any more.

## Three catalogs

| Catalog | Adds to `forms` 1.0 |
|---|---|
| **insight** | `Chart` (bar, line, area, pie, scatter over category, number or time axes), `Sparkline`, `Metric`, `KeyValue`, `Progress`, `Badge` |
| **studio** | insight, plus `App` (pages the host navigates), `Page`, `Region` and `Scene3D` (primitive 3D shapes) |
| **spatial** | studio, plus `Bar3D`, `Scatter3D`, `SurfacePlot`, `Graph3D`, `Globe`, `Scene`, `DepthCard` and `Stage` |

An agent draws with `genui`'s `render_screen` in one of them (`adk_ui::toolset_for`). A home
that registers them (`adk_ui::catalogs::register`) shows what it draws:
- **The ADK-Rust web home** draws charts and 3D natively, in its own palette.
- **The terminal** shows each drawing in words.
- **A host of your own** draws them with `@zavora-ai/adk-ui-react` 3's renderers for
  `DrawnView`.

## 3D that only shows

The spatial catalog brings these to agent-drawn UI:
- 3D charts, networks and globes;
- scenes with groups, lights, cameras, motion and notes beside objects;
- cards with depth, carousels and walls.

The web home draws scenes with WebGL, loaded only for a drawing that has one, and depth effects
with CSS 3D. Each scene comes with a summary the server writes, a text view, and a pause button
for motion. Under reduced motion it holds still.

A scene can't become a decision. Its colours are palette tokens or labelled states, its labels
are checked like any string, and it has no textures, models, fonts, shaders or links. Picking
an object fills a choice field the drawing shows and sends nothing: the drawing's **Send** still
asks the person first.

For 3D the catalog can't express, the `apps` feature's `show_3d_app` runs three.js the model
writes in genui-apps' sandbox, on its own origin. The server refuses code that shows a
decision's words or reaches outside its frame, and the tool calls an app asks for are held for
the person.

## Examples

- `insight_agent`: an agent on Claude that studies a directory and answers with charts, pages
  and 3D, with `show_3d_app` under `ADK_UI_3D_APPS=1`.
- `insight_home`: the web home over a scripted agent that draws eleven sample drawings.
- `examples/custom_host`: a Vite app that draws the same drawings with `DrawnView`, adk-ui's
  renderers and two approved brand kits.

## Compatibility

adk-ui 3 needs ADK-Rust 3.0: `adk-surface` with `genui`, including its scenes and depth effects,
and `@zavora-ai/adk-surface-react` 3 for a host of your own. It needs Rust 1.95 or later and
React 18.3 or 19.

This is a breaking release. Every 2.x render tool, protocol adapter, profile, template and
React renderer is gone. [MIGRATING_TO_3.md](../MIGRATING_TO_3.md) maps each one to its
replacement. adk-ui 2.2 stays on crates.io and npm for ADK-Rust 2, with security fixes only
until the `adk_ui` server profile's sunset on 2026-12-31.
