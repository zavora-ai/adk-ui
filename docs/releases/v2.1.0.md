# ADK UI v2.1.0

ADK UI 2.1 makes protocol capability discovery explicit, improves the quality of interfaces produced by agents, and aligns the React package with the Rust crate on a single version line.

Hosts can now distinguish stable, candidate, partial, host-owned, planned, and legacy behavior instead of relying on a single compatibility label.

## Highlights

- **Versioned capability discovery:** `/api/ui/capabilities` exposes a 2026 schema with protocol versions, maturity, negotiation keys, content types, transports, fallbacks, and scoped claims.
- **A2UI:** v0.9.1 remains the stable surface target while the v1.0 correlated RPC subset is advertised separately as a release candidate.
- **AG-UI:** typed capability snapshots, lifecycle events, reasoning continuity, activity/state streams, and interrupt/resume wire models have explicit support boundaries.
- **MCP Apps:** the bridge targets the 2026-01-26 extension model with typed host capabilities, lifecycle notifications, and progressive fallback behavior.
- **Generated UI quality:** responsive KPI grids, stable component identity, safer nested layouts, persistent form state, and clearer empty/error states improve generated surfaces.
- **Brand kits:** versioned manifests carry provenance, approval state, validated assets, semantic tokens, component recipes, and agent constraints, and one approved `kit_id` now drives every rendering path.
- **Generative applications:** the React package renders a validated multi-page application graph with local routing and preserved visited-page state.

## Version alignment

The React package moves from its own `0.x` line to the release line it implements. `@zavora-ai/adk-ui-react@2.1.0` is the counterpart of `adk-ui = "2.1"`, so a single number now identifies both halves of a deployment.

The public API is a strict superset of the previously published `0.3.2`: 55 values and 78 types are exported, and no export was removed or renamed. Upgrading is additive apart from the optional dependency change below.

## Lighter installs

`three` and `recharts` are now **optional peer dependencies** instead of hard dependencies. Both were already loaded on demand from separate chunks, and neither is reachable from the core renderer path, so hosts that never render a chart or a 3D scene no longer install them.

| Capability | Component | Required package |
| --- | --- | --- |
| Charts | `chart` | `recharts@^3` |
| Declarative 3D | `scene_3d`, A2UI `Scene3D` | `three@>=0.180` |

Skipping both removes roughly 63 MB from a fresh install, measured in a scratch consumer project before and after adding `three` and `recharts` with their transitive packages.

When an agent sends a component whose optional peer is absent, that component degrades to an accessible note naming the package to install, logs the reason once, and leaves the rest of the surface rendered. Previously a missing renderer dependency would have propagated to the host application.

`react`, `react-dom`, `clsx`, `lucide-react`, and `react-markdown` remain required, because the core renderers import them directly.

## Packages

```toml
[dependencies]
adk-ui = "2.1"
```

```bash
npm install @zavora-ai/adk-ui-react@2.1.0

# add only the capabilities you render
npm install recharts   # chart components
npm install three      # scene_3d components
```

## Upgrading from @zavora-ai/adk-ui-react 0.3.2

1. Install `2.1.0`. No import paths or export names change.
2. If your agents render `chart` components, add `recharts` to your own dependencies.
3. If your agents render `scene_3d` or A2UI `Scene3D` components, add `three`.
4. Optionally include `ADK_UI_KIT_CSS` to pick up brand-kit tokens and the styling for the degraded optional-renderer note.

## Validation

- 171 Rust tests pass across the default and feature-enabled suites.
- 51 React protocol, renderer, and packaging tests pass, including five that hide the optional peers from the module resolver.
- `cargo fmt --all -- --check` and `cargo clippy --all-targets --all-features -- -D warnings` pass.
- React lint, typecheck, and production builds pass.
- `npm audit --omit=dev` reports zero vulnerabilities.
- `cargo publish --dry-run` packages the crate cleanly, and `npm pack` produces a 26-file tarball that includes both lazy chunks.
- All five runtime profiles remain smoke-tested in the live Studio.

The React package now runs `lint`, `typecheck`, and the test suite from `prepublishOnly`, so a publish cannot ship an unbuilt or unverified `dist`.
